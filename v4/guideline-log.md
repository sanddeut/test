# 연구2 개선안: 가이드라인 적용 기록

연구1에서 도출한 가이드라인 25개(FigJam '가이드라인 정리' 2안 최신본)를 택시 호출 프로토타입(v4)에 어떻게 적용했는지 기록해요.
수정할 때마다 이 파일도 함께 고쳐요. 확인 화면 번호는 개선안 페이지(연구2 프로토타입 개선안) 기준이고, 화면이 추가되면 바뀔 수 있어요.
아직 적용하지 않은 가이드라인은 적용 내용을 비워 뒀어요.

## 1. 가이드라인별 적용 내용

| 번호 | 상위범주 | 하위범주 | 가이드라인 | 적용 내용 | 확인 화면 | 할 일 / 논의 중 |

| 1 | 사용자 입력 | 입력 방법 | 첫 화면은 입력 방법(상호작용 시작 방법)을 명시적으로 보여 줘야 한다. | ① 첫 화면에 긴 「눌러서 대화 시작」 버튼 하나만 두고, 누르면 「말로 하기」/「글로 하기」 두 버튼이 나타남<br>② 첫 AI 말풍선 안에 안내 상자(ⓘ 이렇게 대화를 시작해보세요: 1. 「눌러서 대화 시작」을 눌러요 2. 말로 할지, 글로 할지 골라요). 말로/글로를 고른 뒤에는 숨김<br>③ 「글로 하기」를 누르면 바로 키보드가 올라옴. 입력창 안내 문구는 "여기에 적어 주세요"(원안 "AI에게 말하기"는 말로 하라는 뜻으로 헷갈림)<br>④ 말로 하기에서는 글 입력창을 없애고 [눌러서 말하기]와 [보내기]를 한 줄로 묶음. 별도 마이크 버튼은 없앰. 보내기 버튼에 "보내기" 글자<br>⑤ 입력창 위 작은 버튼으로 말로/글로 전환 | 0번 행 (대화 시작) | |
| 2 | 사용자 입력 | 입력 피드백 | 시스템은 사용자의 입력이 오류 없이 전달되었는지를 즉시 알려야 한다. | ① 사용자가 보낸 순간 그 말풍선 옆에 작은 동그라미 체크(stroke, 차분한 초록)가 잠깐 보였다가 사라짐. 지나간 단계 표시가 아니라 전달 확인 용도<br>② 말로 하기: 듣는 중에는 "듣고 있어요 …" 빨간 칩이 작아지며 위로 올라가고, 받아 적는 내용이 흰 영역에 바로 보임<br>③ 버튼을 눌러야 듣는다는 점을 강조. 계속 듣기나 소리 감지는 혼잣말, 소음 문제로 채택하지 않음<br>④ 글을 쓰고 4초 동안 보내지 않으면 "보내기를 눌러야 전달돼요" 안내 (4번에도 해당) | 0번 행 | |
| 3 | 사용자 입력 | 입력 피드백 | 시스템은 사용자의 요청이 수행되지 않았을 때 그 이유와 대안을 알려야 한다. | |<br>AI가 앱 화면을 누르는 중에 말이나 글로 요청하면 "지금은 앱 화면을 누르는 중이라 바로 바꿀 수 없어요. 이 단계가 끝나면 바로 반영할게요."라고 이유와 대안을 짧게 알리고, 화면 조작이 끝나면 그 요청을 반영 (연구1 P01: 진행 중 말로 요청했는데 반영되지 않고 이유도 몰랐음) | (동작) | |
| 4 | 사용자 입력 | 입력 피드백 | 시스템은 사용자가 알아야 할 내용을 확실히 인지할 수 있도록 두드러지게 전해야 한다. | ① 글을 쓰고 4초 동안 보내지 않으면 "보내기를 눌러야 전달돼요" 안내 (2번에도 해당)<br>② 글뿐 아니라 화면 변화로도 전함: 실행화면 테두리의 움직이는 그라데이션, 「내가 조작하기」 전환 모션 | 0번 행 (보내기 안 누름), 실행화면 전체 | |
| 5 | 사용자 입력 | 입력 피드백 | AI는 사용자의 입력을 실행하기 전에, 무엇을 하려는지 먼저 알려야 한다. | |<br>출발지와 목적지는 찾아 둔 뒤 실행하기 전에 "출발지를 ‘신분당선 동천역’으로 설정할게요. 여기가 맞나요?", "‘담소한정식 강남점’을 찾았어요. 여기가 맞나요?"라고 먼저 확인. 알아서 하는 단계도 "택시 앱을 실행할게요."처럼 하기 전에 알림 (사용자가 잘못 말했거나 잘못 알아들었을 수 있으므로) | 출발지, 목적지 화면 | |
| 6 | 에이전트 활동 설명 | 주체 구분 | 화면은 지금 AI와 사용자 중 조작권이 누구에게 있는지 보여 줘야 한다. | ① AI가 조작할 때: 실행화면 상단 가운데 탭 모양 칩 "AI가 앱 조작 중", 움직이는 테두리(파랑, 보라, 분홍), 앱 화면 위 흰색 30% 덮개<br>② 사용자가 조작할 때: 앱 헤더를 연한 붉은색으로, "직접 조작 중" 칩은 흰 바탕에 붉은 글씨<br>③ 대화창: AI가 작업 중일 때 움직이는 점 아래에 작게 "AI가 앱 조작 중" (진행 카드 안에는 넣지 않음) | 실행화면 전체, 24번 | |
| 7 | 에이전트 활동 설명 | 주체 구분 | 화면은 AI가 대신 정한 내용을 사용자가 한 것과 구분되도록 분명히 표시해야 한다. | 버튼으로 답한 사용자 말풍선은 "승인"/"거부" 아랫줄에 무엇에 답했는지 작은 글씨로 표시(예: 승인 / 택시 앱 실행) | 진행 카드 화면들 | |
| 8 | 에이전트 활동 설명 | 진행 현황 | 화면은 지금 진행 중인 단계가 무엇인지 분명히 알려야 한다. | 지금 단계가 항상 대화창 맨 위에 오도록 지난 대화를 위로 올림. 지난 대화는 흐리게 하지 않고 위쪽 가장자리만 그라데이션으로 흐려져, 위에 지난 기록이 있음을 알림(스크롤하면 또렷하게 보임) | 진행 카드 화면들, 48번 | |
| 9 | 에이전트 활동 설명 | 진행 현황 | 화면은 사용자가 지금 행동해야 하는지 기다려야 하는지를 명확히 보여 줘야 한다. | ① 기다릴 때: 카드 바깥 위에 AI 아이콘과 움직이는 점만<br>② 행동할 때: 점이 있던 줄이 사라지고 질문과 승인/거부만 보임<br>③ 작업 중에 결과를 보여 줄 때(높은 자동화): 점이 먼저, 그 아래 결과 카드가 차례로 나타남 | 10번, 80번 | |
| 10 | 에이전트 활동 설명 | 정보 제시 | 화면은 핵심 정보만 간결하게 보여 주고, 부가 정보는 사용자가 원할 때 확인할 수 있게 해야 한다. | ① 진행 카드의 "할 일 처리하는 중" 제목, "확인이 필요해요" 줄 삭제. 작업 중 진행 문장(대화에 이미 있음) 대신 점만<br>② 실행화면 상단 "작업 진행 중" 제목 삭제<br>③ 뒤로 가기 다이얼로그의 서브텍스트, 구분선, 타이틀 아이콘 삭제<br>④ 대화창 배경을 흰색으로, AI 말풍선과 진행 카드는 옅은 회색, 사용자 말풍선은 파란색. 카드 안의 카드는 흰색<br>⑤ 「실행화면 보기」 버튼은 테두리 없이 옅은 흰 바탕과 회색 글씨로 강조를 줄여 다른 내용이 잘 보이게 함<br>⑥ 진행 카드를 [발화와 카드] 묶음과 [사용자 버튼] 묶음으로 나눔: 사이에 옅은 구분선과 넉넉한 여백. 발화와 카드 사이도 넉넉히 띄워 발화가 묻히지 않게. 거부/승인 버튼은 조금 작게<br>⑦ 진행 카드의 발화 문장을 굵게 해 주인공으로, 장소/앱/선택지/호출 내용 같은 카드 안의 카드는 글씨와 아이콘을 한 단계 작게 해 보조 정보로<br>⑧ 택시 종류 카드는 세 가지 옵션을 처음부터 펼쳐 보이고, "택시 종류" 머리 줄은 삭제해 핵심 정보만 남김 (원안도 함께 수정. 연구1 실험 때 세 가지가 보였던 것에 맞춤) | 10번, 80번, 실행화면 전체, 뒤로 가기 행 | |
| 11 | 에이전트 활동 설명 | 정보 제시 | 시스템은 사용자가 읽고 확인할 시간을 충분히 제공해야 한다. | |<br>알아서 진행하는 단계(택시 앱 실행, 예상 금액)는 결과 카드를 보여 준 뒤 더 오래 머묾. 일시정지 버튼은 따로 두지 않고 「멈추기」(멈춘 뒤 계속하기)로 대신함 | 택시 앱 실행, 예상 금액 화면 | |
| 12 | 사용자 통제 | 중지 수단 | 화면은 중지 수단의 위치와 기능을 한눈에 알아볼 수 있게 보여 줘야 한다. | AI가 작업 중일 때 입력창의 보내기 버튼 자리에 빨간 「멈추기」 글자 버튼 (원안: 빨간 네모 아이콘)<br>실행화면 아래 한 칸에 「멈추기」(흰 바탕 빨간 테두리)와 「내가 조작하기」(빨간 바탕)를 묶어 둠. 오른쪽 위 「?」를 누르면 AI가 잠시 멈추고 화면이 어두워지며 실행화면, 멈추기, 내가 조작하기를 차례로 짚어 짧게 안내(「다음」, 「알겠어요」) | 진행 카드 작업 중 화면 | |
| 13 | 사용자 통제 | 실행 중 개입 | 화면은 사용자가 AI로부터 조작권을 언제든 회수할 수 있음을 드러내야 한다. | 실행화면 아래 가운데 빨간 「내가 조작하기」 버튼(그림자, 아이콘 없이 작게). 누르면 화면이 전체로 커지고, 흰 배경 로딩 스피너 뒤 바운스하며 앱 화면으로 바뀜<br>「?」 안내에서 "AI 대신 내가 직접 앱을 눌러요." | 내가 조작하기 행 | |
| 14 | 사용자 통제 | 실행 중 개입 | 시스템은 결과가 확정되기 전에 사용자가 개입할 시점을 보장해야 한다. | |<br>결과가 정해지는 순간(출발지, 목적지, 택시 종류, 기사님 요청사항, 최종 호출)마다 먼저 묻거나 확인한 뒤 진행. 진행 중에도 「멈추기」, 「되돌리기」로 개입 가능 | 진행 카드 화면들 | |
| 15 | 사용자 통제 | 수정과 되돌리기 | 시스템은 사용자가 AI의 결정을 수정하는 방법을 알고 쉽게 수정할 수 있도록 해야 한다. | 이미 끝낸 단계에 승인/거부로 답한 사용자 말풍선 아래 작은 「되돌리기」 텍스트 버튼(답할 일이 없던 높은 자동화 단계는 AI 말풍선 아래). 누르면 그 단계 시작 전 상태로 되돌리고 그 단계를 다시 물음(높은 자동화도 이 단계는 물어봄). 현재 카드를 맨 위보다 조금 아래에 두어 「되돌리기」가 살짝 보이게 함 | 진행 카드 화면들 | |
| 16 | 사용자 통제 | 수정과 되돌리기 | 시스템은 결과가 확정된 뒤에도 사용자가 되돌릴 수 있게 해야 한다. | 「방금 한 일 취소」(뒤로 가기 다이얼로그)와 「되돌리기」: 바로 전에 끝난 단계를 되돌리고 "방금 한 일을 되돌렸어요. ○○부터 다시 할게요."라고 알린 뒤 다시 물음. 최종 호출 확인에 답한 뒤에는 되돌릴 수 없음 | 뒤로 가기 행 | |
| 17 | 사용자 통제 | 승인과 위임 범위 | 시스템은 AI의 제안을 사용자가 쉽게 거절할 수 있게 해야 한다. | 거부한 뒤 AI가 되물을 때 추천 선택지를 목록으로 함께 보여 줌(말이나 글로 답해도 됨). 택시 앱: 마음택시 실행 / 그만하기. 출발지: 현재 위치 / 직접 입력. 택시 종류: 일반 / 모범 / 대형. 쿠폰: 쿠폰 적용 / 적용 안 함. 최종 호출: 출발지 바꾸기 / 목적지 바꾸기 / 택시 종류 바꾸기 / 호출 취소(고르면 그 항목의 선택지가 이어서 나옴). 목적지는 추천 없이 직접 말하거나 입력 | 거부 화면들 | |
