# 연구1 · 송금 에이전트 시나리오 프로토타입

「연구1 시나리오 설계」의 2×2 조건(복잡도 A/B × 자동화 낮음/높음)을 참가자가 직접 체험하는 웹 프로토타입이에요.
참가자는 폰 화면 속 AI 도우미에게 말(글·음성)로 송금을 요청하고, 에이전트는 **30만원을 10만원으로 잘못 알아듣는 오류 1회**를 포함한 스크립트대로 진행해요.

## 실행

빌드나 설치가 필요 없어요. 정적 파일이라 아무 웹서버로 열면 돼요.

```bash
python3 -m http.server 8000
# 브라우저에서 http://localhost:8000
```

GitHub Pages에 올려도 그대로 동작해요.

**휴대폰에서 주소창 없이 보기**: 설정 화면 맨 아래 「웹에서 보기」(세션 시작)를 누르면 안드로이드 크롬에서 전체화면으로 바뀌어요. 이때 크롬이 하단에 전체화면 종료 안내를 잠깐 띄우는데, 이건 브라우저 기능이라 숨길 수 없어요. 크롬 메뉴의 「홈 화면에 추가」로 설치한 아이콘으로 열면 그 안내 없이 처음부터 주소창 없이 열려요(manifest.json). **모바일 퍼스트**로 만들어서 참가자 휴대폰으로 바로 접속하면 화면 전체가 에이전트 화면이 돼요. PC에서는 가운데 모바일 폭 화면과 옆의 과업 카드로 보여요.

## 화면 구성 (현행 서비스 3종 비교 결과 반영)

메타 뮤즈, chatGPT Work, 제미나이 에이전트를 비교해서 가장 많이 쓰는 방식을 골랐어요.

| 항목 | 연구1 프로토타입 |
|---|---|
| 기본 화면 | 대화창 |
| 실행화면 | 대화창에는 보이지 않고, 진행 카드의 「실행화면 보기」를 누르면 크게 보여요 |
| 사용자 입력 | 필요한 정보는 대화창 안에 자체 UI(승인/거부 버튼, 선택 목록, 비밀번호 키패드)로 받아요. 팝업 직접 닫기처럼 필요할 때만 앱 화면으로 전환해요 |
| 직접 조작/중지 | 대화창에서는 작업 중에 입력창의 보내기 버튼이 중지(■) 버튼으로 바뀌고, 중지하면 에이전트가 「직접 조작 / 계속하기」를 물어봐요. 실행화면에서는 아래 「중지」「직접 조작」 버튼을 바로 눌러요. 직접 조작을 누르면 앱 화면으로 전환돼요 |
| 작업내역 | 진행 카드에 지금 하는 작업을 짧게 보여주고, 로그는 남기지 않아요 |

- **대화창 (기본)**: 과업을 요청하면 대화창에 진행 카드(「할 일 처리하는 중」 + 「실행화면 보기」)가 생겨요. 카드 안의 짧은 문구가 실제 화면 진행에 맞춰 바뀌고(예: “문자 목록 확인 중”), 버튼으로 답하는 질문(승인/거부, 출금계좌 목록, 비밀번호 키패드)은 메타 뮤즈의 승인 카드처럼 **진행 카드 안에 질문과 선택지가 함께** 나오고, 질문하는 동안에는 「실행화면 보기」를 숨기고, 대신 판단에 필요한 내용을 재구성한 UI를 함께 보여줘요: 문자 앱·은행 앱 아이콘, 문자 속 계좌번호, 이벤트 팝업 내용, 출금계좌와 잔액, 받는 계좌, 보낼 금액, 통장표기, 최종 송금 내용 요약. 답하면 그 질문은 AI 말풍선으로 대화 기록에 남고, 카드는 맨 아래로 내려와 진행을 이어서 보여줘요. 말로 답하는 질문(거부 후 “무엇을 수정할까요?” 등)은 AI 말풍선으로 나오고, 그동안 진행 카드는 숨겨져요. 참가자가 답할 때는 말풍선 자리에 “…”이 잠깐 보인 뒤 에이전트가 반응해요. 높은 자동화(A2·B2)에서도 정보량을 맞추기 위해, 에이전트가 알리는 문구와 같은 재구성 UI를 카드에 함께 보여줘요(승인 버튼만 없음, 「실행화면 보기」는 계속 보임). 낮은 자동화의 승인·선택 질문 카드 아래에는 chatGPT의 “Sign in manually instead”처럼 작은 「직접 조작하기」 링크가 있어요. 다음 단계로 넘어가면 앞의 알림 문구는 AI 말풍선으로 기록에 남아요. 끝나면 카드가 「할 일 마무리」로 바뀌어요.
- **진행 화면 (실행화면 보기)**: 앱 화면 전체를 고정된 크기로 축소해서 보여주고, 아래에 에이전트 문구를 표시해요. 승인/거부는 알약 버튼, 출금계좌처럼 여러 선택지는 세로 목록으로 바로 눌러요. 왼쪽 위 뒤로 버튼(‹)을 누르면 대화창으로 돌아가요. 화면 맨 아래 왼쪽에 「중지」, 오른쪽에 「직접 조작」 버튼이 있어요.
- **에이전트 조작 연출**: 축소 화면에서 에이전트가 실제로 조작하는 과정이 보여요. 누르는 곳에 터치 표시가 뜨고, 작업하는 동안에는 화면 테두리가 파랗게 빛나요.
  - 문자 목록에서 김영숙 문자를 누르고, 계좌번호를 길게 눌러 복사
  - 계좌 카드의 [이체] → 「추천」에서 「자주」 탭으로 이동 → 김영숙 계좌 선택 (B는 계좌번호 칸에 붙여넣기 → 은행 선택)
  - 금액은 승인 후 키패드로 한 자리씩 입력 → [확인], 금액을 고치면 지우고 다시 입력
  - 받는 분 통장표기를 누르고 메모를 한 글자씩 입력 → [다음] → 확인 시트에서 [이체]
- **로딩**: 앱을 실행하면 스플래시 화면, 은행 앱 안에서 화면이 바뀌면 로딩 스피너가 보여요. 가끔은 조금 더 길게 버퍼링돼요.
- **비밀번호**: chatGPT처럼 앱 화면으로 넘기지 않고, 대화창 안의 비밀번호 카드(보안 키패드)에 4자리를 입력해요. 키패드 아래 「은행 앱에서 직접 입력하기」를 누르면 흰 화면과 스피너가 잠깐 보인 뒤 앱 화면 전체로 바뀌어 은행 앱의 비밀번호 창에 직접 입력할 수도 있어요(뒤로 ‹를 누르면 대화창 키패드로 돌아감). 실행화면을 보고 있었어도 대화창으로 돌아와 입력하고, 입력이 끝나면 「비밀번호 입력 완료」만 남아요.
- **진행 문구**: “계좌를 확인하고 있어요 …”처럼 “…”으로 끝나는 문구는 진행 카드(실행화면에서는 하단 문구)에만 잠깐 보이고, 다음 문구가 나오면 사라져요. 대화창 말풍선으로는 남지 않아요.
- **말로 답해야 할 때**: 실행화면을 보고 있다가도 “어떻게 바꿀까요?”, “어떤 앱으로 실행할까요?”, 중지 후 대화처럼 말로 답해야 하면 대화창으로 전환돼요.
- **이체 완료**: 실행화면을 보고 있었다면 이체 완료 화면이 [확인]을 누를 때까지 그대로 있고, 누르면 대화창으로 돌아가요. 대화창에 있었다면 완료 안내가 바로 대화창에 나와요.
- **중지**: 대화창에서는 에이전트가 작업하는 동안 입력창 오른쪽 버튼이 ■ 중지 버튼이 돼요(글자를 입력하면 다시 보내기 버튼). 참가자의 답을 기다리는 동안에는 보내기 버튼이에요. 누르면 (실행화면에 있었다면 대화창으로 돌아가고) “진행을 멈췄어요. 어떻게 바꿀까요?”가 나와요. 참가자가 말하면 응답하거나 금액·메모·출금계좌를 바꾸고, 「계속하기」를 누를 때까지 멈춰 있어요. 이때 「직접 조작」도 함께 제시돼서, 누르면 앱 화면에서 직접 고칠 수 있어요. 낮은 자동화에서 내용이 바뀌었으면 계속하기 후 그 단계 질문을 다시 해요.
- **직접 조작 화면**: 직접 조작, 팝업 직접 닫기 때는 앱 화면이 실제 크기로 보여요(실행화면에서 누르면 축소 화면이 부드럽게 커져요). 왼쪽 위 뒤로(‹)를 누르면 “이어서 진행할게요” 같은 안내 없이 대화창과 직전 질문 카드로 그대로 돌아가요. 낮은 자동화에서 값이 바뀌었으면 바뀐 값으로 다시 물어요. 직접 조작 중에는 금액 키패드, 출금계좌(「마음은행 계좌에서 ⌄」 탭), 메모를 고칠 수 있어요.
- **마음은행 앱**: 실제 모바일 뱅킹 앱의 흐름을 따라 만들었어요. 홈 계좌 카드 → 「어디로 이체하시겠어요?」(추천/자주/내계좌) → 금액 키패드 → 받는 분 통장표기 → 이체 확인 → 비밀번호 → 완료. 은행 이름과 로고는 가상이에요.
- 상황·과업 카드는 세션을 시작할 때 한 번 떠요. PC에서는 화면 옆에 계속 보여요.

## LLM (Gemini) 연결

- **키 설정은 연구자 전용 페이지(`key.html`)에서 해요.** 주소 끝에 `key.html`을 붙여 열고(예: `https://sanddeut.github.io/test/key.html`), Gemini API 키와 모델을 넣고 「저장」을 눌러요. 기본 모델은 `gemini-3.5-flash`예요.
- 같은 페이지의 「키가 담긴 공유 링크 복사」로 만든 링크를 보내면, 받은 분이 한 번 여는 것만으로 그 기기에 키가 저장돼요. 키 부분은 주소창에서 바로 지워지고, 이후에는 키를 입력할 필요가 없어요.
- 메인 페이지 설정 화면에는 키 입력칸 대신 연결 상태만 보여요. 키가 없으면 규칙 기반 해석으로 동작해요.
- 키를 코드에 넣지 않는 이유: 저장소가 공개라 누구나 키를 볼 수 있고, 구글이 노출된 키를 자동으로 막을 수 있어요. 필요하면 Google AI Studio/Cloud 콘솔에서 키에 웹사이트 제한(`sanddeut.github.io/*`)과 사용량 한도를 걸어두세요.
- **설정 화면 맨 아래 버튼:** 「웹에서 보기」는 이 브라우저에서 바로 세션을 시작하고, 「앱 설치」는 안드로이드 크롬에서 설치 창을 띄워요(설치 창을 띄울 수 없으면 직접 설치하는 방법을 버튼 아래에 안내). 설치한 앱으로 열면 「앱 설치」 없이 「세션 시작」 버튼만 보여요.
- **안드로이드:** 설치한 앱과 크롬이 저장 공간을 같이 써서, 링크를 크롬에서 한 번 열면 앱에도 키가 들어가요.
- **아이폰:** 홈 화면 앱은 사파리와 저장 공간이 분리돼 있어요. 키가 없으면 설정 화면 아래에 빨간 글씨로 「Gemini 연결 안 됨」이 보여요. 이 글씨를 누르면 「받은 링크 붙여넣기」 칸이 열리니, 받은 링크를 한 번 붙여넣어 주세요.
- **고정 문구는 스크립트, 스크립트 밖 응답은 LLM**이 만들어요. 에이전트의 정해진 문구와 순서는 `js/scenarios.js`에 고정돼 있어요. 참가자가 예상 밖의 말을 하면 LLM이 연구팀 프롬프트(`js/llm.js`의 `LLM_SYSTEM`)에 따라 응답해요.
  - 매 턴 자동화수준, 현재 단계, 현재 단계의 에이전트 문구, 최근 대화를 함께 전달해요.
  - 낮은 자동화에서는 승인을 묻는 형태로, 높은 자동화에서는 진행 상황을 알리는 형태로 답하고 자동 진행을 이어가요.
  - 지정된 앱이 아닌 앱(다른 은행 앱, 전화 등)을 말하면 그 앱으로는 송금할 수 없다고 알리고 은행 앱으로 안내해요.
  - 오류(10만원) 단계에서는 먼저 오류를 암시하지 않고, 참가자가 고쳐달라고 할 때만 금액을 바꿔요.
  - 의도 분류와 값 추출도 함께 해요: 승인·거부, 금액(“삼십만원” → 300,000), 메모, 출금계좌, 계좌번호.
- 키가 없거나 호출이 실패하면 **규칙 기반**으로 전환돼요. 답변을 유형별로 나눠 정해진 문구로 응답하고, 전환된 사실은 로그에 남아요.

## 프롬프트 직접 수정하며 테스트하기

- **설정 화면 → 프롬프트** (접힌 섹션): 스크립트 밖 응답을 만드는 프롬프트를 바로 고칠 수 있어요. 고친 내용은 이 브라우저에 자동 저장돼요. 응답 형식(JSON) 지시는 편집 대상이 아니고 항상 뒤에 자동으로 붙어요. 기본값으로 되돌리려면 편집칸을 비우고 새로고침하면 돼요.
- **세션 중 수정**: 연구자 패널의 프롬프트 칸에서 고치고 「적용」을 누르면 다음 응답부터 반영돼요.
- 프롬프트마다 버전(짧은 해시)이 붙어요. 세션 로그에는 시작 시점의 프롬프트 전문과 버전이 남고, 요약 CSV에는 `prompt_version` 열이 들어가요.

## 시나리오 문구 직접 수정하기

- **설정 화면 → 시나리오 문구** (접힌 섹션): A1·A2·B1·B2 탭을 골라 단계별 에이전트 문구를 고칠 수 있어요. 고친 내용은 이 브라우저에 자동 저장되고, 수정한 조건 탭에는 •이 붙어요.
- 한 줄이 말풍선 하나예요. 자리표시자 `{금액}` `{이름}` `{메모}` `{출금계좌}` `{받는분}` `{계좌번호}`는 진행 중 실제 값으로 바뀌어요.
- 거부 후 되묻는 말, 중지 후 문구, 취소 문구 같은 분기 문구도 함께 고칠 수 있어요.
- 수정한 항목에는 「기본값」 버튼이 떠서 그 항목만 되돌릴 수 있어요.
- 세션 로그에는 수정한 문구와 문구 버전이 남고, 요약 CSV에는 `script_version` 열이 들어가요.

## 조건별 동작 (수정본 기준)

| | 낮은 자동화 (A1, B1) | 높은 자동화 (A2, B2) |
|---|---|---|
| 진행 | 판단 지점마다 승인 요청 | 승인 없이 자동 진행 (단계 간격은 설정에서 조절) |
| 오류 대응 | 「거부」 → “무엇을 수정할까요?”(A) / “어떻게 바꿀까요?”(B) → 수정 금액 확인 | 「■ 중지」 또는 말 걸기 → “진행을 멈췄어요. 어떻게 바꿀까요?” / 「✋ 직접조작」 → 화면에서 직접 수정 |
| 비밀번호 | 이체 직전 계좌 비밀번호 4자리 직접 입력 (모든 조건 공통) | |

- 광고 팝업은 **높은 복잡도(B)에서만** 떠요.
- B는 문자 앱에서 총무 문자를 찾아 계좌를 복사하는 단계와 ‘30기 {이름}’ 메모 단계가 추가돼요.

낮은 자동화에서 「거부」를 누르면 단계별로 이렇게 처리해요.

| 단계 | 거부 후 |
|---|---|
| 앱 실행 | “어떤 앱으로 실행할까요?” → 지정된 앱이면 실행, 다른 앱이면 그 앱으로는 할 수 없다고 알리고 지정된 앱 실행을 다시 물음 |
| 받는 계좌 / 문자 속 계좌 | “어떤 계좌로 송금할까요?” → 다른 계좌를 찾아달라고 하면 같은 계좌와 직접 입력 가능을 안내, 계좌번호를 말하면 그 계좌로 입력 |
| 광고 팝업 | LLM이 상황에 맞게 응답 (예: “알겠어요. 팝업 내용을 보시고 직접 닫으시면 이어서 진행할게요.”) → 참가자가 폰 화면에서 직접 닫으면 진행 |
| 송금액 (오류) | 금액을 말하면 “송금액 30만원을 입력할까요?”로 확인, 금액 외 요청이면 LLM이 응답하고 흐름으로 복귀 |
| 메모 | “어떻게 메모를 남길까요?” → 말한 문구로 다시 확인 |
| 최종 확인 | “무엇을 수정할까요?” → 금액·출금계좌·메모 수정 후 다시 확인, 그 외 요청이면 LLM이 응답하고 흐름으로 복귀 |

## 연구자 패널 (설정 화면 우측 상단 버튼, 세션 중에는 상단 제목 세 번 탭 또는 Ctrl + .)

- 진행 단계, 실시간 이벤트 로그 (에이전트 발화, 참가자 입력, LLM 해석 결과와 지연 시간)
- 요약 지표: 오류 결과(최종 이체 금액 기준 수용/수정/취소, 송금액 단계에서의 결정은 `amount_step_decision`), 개입 방식, **오류 문구 노출 → 반응까지 걸린 시간**, 최종 금액, 승인 응답 수, 중지·직접조작 횟수
