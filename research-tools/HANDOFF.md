# 인수인계: 연구2 개선안 작업 내역

이전 세션(2026-10-22)에서 사용자와 함께 정한 내용이에요. 가이드라인별 적용 내용은 `v4/guideline-log.md`에 더 자세히 있어요.

## 사용자와 일하는 방식

- 가이드라인을 어떻게 반영할지는 사용자와 하나씩 같이 정해요. 먼저 마음대로 바꾸면 안 돼요(이 점 때문에 여러 번 지적받았어요).
- 제안할 때는 짧은 표나 선택지로, 추천안을 하나 표시해요.
- 사용자는 피그마에 직접 시안을 그려 보여 주기도 해요. 피그마 파일 키 UMzRvAM4ZUz5GLOScpMSh6 (Figma MCP는 Education 요금제 호출 한도가 있어요).
- 사용자가 화면 캡처를 보내며 조정을 요청하는 경우가 많아요. 바꾼 뒤 해당 화면을 캡처해 확인하고 페이지를 다시 올려요.
- 글은 짧게. 문장마다 핵심만. 가운데점 금지, 꺾쇠 대신 작은따옴표.

## 개선안 전체 구조 (가장 큰 결정)

- 연구2는 낮은/높은 자동화로 나누지 않고 하나의 프로토타입. 가이드라인 18번(사소한 단계는 알아서, 중요한 결정은 확인)에 따라 단계마다 확인 수준을 정함.
  - 알아서 하고 알림: 택시 앱 실행, 예상 금액(쿠폰은 적용하지 않고 알림. 최종 호출 확인에서 함께 확인)
  - 확인("여기가 맞나요?"): 출발지, 목적지 (사용자가 잘못 말했거나 AI가 잘못 알아들었을 수 있으므로, 가이드라인 5번)
  - 먼저 물음(목록): 택시 종류(요금이 달라지는 선호), 기사님 요청사항(가이드라인 20번, 연구1 세션1 오류 상황을 없앰)
  - 반드시 확인: 최종 호출
  - 세션2: 이용내역을 보기 전에 이유와 함께 허용을 묻고(21번), 예약도 먼저 물음(18번)
- 버튼 이름은 질문의 무게에 맞게(19번): 수정/확인, 거부/허용, 거부/예약하기, 수정/호출하기. '승인'은 무거워서 쓰지 않음.
- 구현: `newSession`에서 조건을 B1로 고정하고 `STEP_POLICY`, `runByPolicy`로 단계별 처리 (`v4/js/improve.js`).

## 화면 디자인 결정

- 첫 화면: '눌러서 대화 시작' 버튼 하나, 누르면 '말로 하기'/'글로 하기'. 첫 AI 말풍선 안에 시작 안내 상자(고른 뒤 숨김). 시작할 때 권한 다이얼로그("AI와의 대화에서 무엇을 허용할까요?", 항목별 토글, 버튼은 '확인' 하나).
- 입력: 글로 하기 안내 문구 "여기에 적어 주세요". 말로 하기는 [눌러서 말하기]와 [보내기]만. 말로/글로 전환 버튼은 옅은 회색 테두리, 입력창과 간격 10px.
- 전달 확인: 보낸 순간 말풍선 옆에 초록 동그라미 체크(stroke)가 잠깐 보였다 사라짐. 4초 동안 안 보내면 "보내기를 눌러야 전달돼요".
- 대화창: 흰 배경, AI 말풍선과 진행 카드는 아주 옅은 회색(#f5f6f8), 사용자 말풍선 파랑. 말풍선 간격 18px.
- 진행 카드: 제목과 "확인이 필요해요" 줄 없음. 작업 중에는 카드 바깥 위에 AI 아이콘과 움직이는 점, 그 위에 작게 "AI가 앱 조작 중". 결과 카드는 점 다음에 차례로 나타남. 발화 문장은 굵게(600), 카드 안의 카드는 흰색이고 한 단계 작게, 선택지 글씨는 보통 굵기. [발화와 카드] 묶음과 [버튼] 묶음 사이에 옅은 구분선과 넉넉한 여백. '실행화면 보기'는 테두리 없이 약하게.
- 지난 대화: 현재 단계를 맨 위(위 여백 84px)에 두고 위쪽 가장자리만 그라데이션으로 흐림. 지난 대화 전체를 흐리게 하거나 "완료" 글자를 붙이는 안은 뺐음.
- 승인/거부 말풍선: 큰 글씨로 '확인' 등, 아랫줄에 작은 글씨로 무엇에 답했는지(예: 목적지 설정).
- 되돌리기: 이미 끝낸 단계의 사용자 답 말풍선 아래 작은 '되돌리기'. 누르면 그 단계 시작 전 상태로 돌리고 다시 물음. 뒤로 가기 다이얼로그의 '방금 한 일 취소'도 같은 동작. 최종 호출에 답한 뒤에는 불가.
- 수정(거부) 후: 진행 카드 안에 질문과 추천 선택지 목록(기사님 요청사항 카드와 같은 모양). 출발지: 현재 위치/직접 입력, 택시 종류: 세 가지, 최종 호출: 출발지/목적지/택시 종류 바꾸기, 호출 취소. 목적지는 추천 없음.
- 멈추기: 빨간 네모 아이콘 대신 '멈추기' 글자 버튼. 일시정지 버튼은 따로 없음.
- 진행 중 요청: AI가 화면을 누르는 중이면 "지금은 앱 화면을 누르는 중이라 바로 바꿀 수 없어요. 이 단계가 끝나면 바로 반영할게요."라고 알리고, 끝나면 반영(가이드라인 3번, 연구1 P01).
- 실행화면: 앱 화면과 아래 버튼 칸('멈추기' 흰 바탕 빨간 테두리, '내가 조작하기' 빨간 바탕)을 하나의 테두리로 묶음. 테두리는 파랑과 보라 두 가지 색 그라데이션이 돎. 위 가운데 "AI가 앱 조작 중 ..." 탭 칩, 앱 화면 위 흰색 30% 덮개. 오른쪽 위 '?' 안내.
- '?' 안내: AI를 잠시 멈추고 화면을 어둡게 한 뒤 실행화면, 멈추기, 내가 조작하기를 차례로 말풍선 툴팁으로 설명. "1 / 3"과 '다음'은 화면 아래. 밝게 남기는 영역은 대상에 딱 맞춤.
- 내가 조작하기: 누르면 화면이 커지고 흰 로딩 뒤 앱 화면으로 바운스. 직접 조작 중에는 헤더가 연한 빨강, "직접 조작 중" 칩은 흰 바탕 빨간 글씨.
- 뒤로 가기: 가운데 다이얼로그 "진행을 멈췄어요 / 어떻게 할까요?" + 계속하기, 방금 한 일 취소, 앱 종료(회색). 앱 종료는 한 번 더 확인.
- 택시 종류 카드: 원안과 개선안 모두 세 가지를 처음부터 펼쳐 보이고 "택시 종류" 머리 줄은 없앰(연구1 실험 때와 같게).

## 정리 페이지 규칙

- 연구2 비교 페이지: 원안 낮은 자동화 / 원안 높은 자동화 / 개선안 세 칸. 개선안에만 있는 장면은 원안 칸에 "해당없음". 같은 화면이어도 캡처를 그대로 넣음.
- 가이드라인 적용 페이지: 범주(큰 제목) > 소제목 > 가이드라인 토글(처음엔 모두 접힘, 같은 소제목은 한 카드에 구분선으로). 펼치면 항목마다 원안 → 개선안 캡처와 설명 불릿. 설명은 "원안의 문제와, 무엇을 위해 어떻게 개선했는지" 중심으로. 페이지에서 '문구 편집'으로 직접 고칠 수 있고(아티팩트 db), 고친 내용은 `build_guides.py`에 옮겨 둠.
