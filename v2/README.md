# 연구1 프로토타입 v2 · 택시 호출

루트의 송금 프로토타입은 그대로 두고, 과업을 **택시 호출**로 바꾼 버전이에요. 송금 버전의 원칙(2×2 조건, 에이전트 오류 1회, 낮은 자동화=단계별 승인 / 높은 자동화=안내 후 진행, 중지·직접 조작)과 화면 구성은 그대로예요.

- 주소: `https://sanddeut.github.io/test/v2/` (연구자 페이지: `v2/key.html`)
- 기존 버전과 같은 도메인이라 **Gemini 키·모델은 공유**돼요. 세션 기록·문구 수정·설정은 `v2:` 접두어로 따로 저장돼요.

## 과업

| | 상황 | 과업 |
|---|---|---|
| A | 오늘 저녁 7시 동창회 모임 장소는 ‘담소한정식 강남점’. 동천역으로 걸어가는 중이라 택시는 ‘신분당선 동천역’에서 타려고 함 | ① 출발지를 신분당선 동천역으로 바꾸기 ② 강남점으로 가는 택시 호출 |
| B | (A와 같음) + 정장이라 모범택시를 타려 하고, 택시 앱의 할인 쿠폰도 쓰려고 함 | ① 출발지 바꾸기 ② 택시 호출 ③ 모범택시로 바꾸기 ④ 할인 쿠폰 적용 |

- 출발지 기본값은 휴대폰 GPS 현재 위치(권한 거부·실패 시 판교역 부근). 실제 지도와 도로 경로를 보여줘요.
- 목적지는 검색 결과(강남구청점·강남점·역삼점)에서 에이전트가 강남점을 맞게 골라요.
- 결제는 모든 조건에서 자동결제(마음카드 ****1234). 결제 방식 단계는 없어요(`USE_PAY_STEP`).
- **직접조작 1회 (모든 조건)**: 호출 직전 참가자가 결제 비밀번호 4자리를 택시 앱 화면에서 직접 입력. 대화창에는 [화면 열기] 버튼만 있고, 누르면 대화창이 튕기듯 작아지며 왼쪽으로 빠지고 앱 전체 화면이 오른쪽에서 들어옴(입력 후 반대로 돌아옴).
- 낮은 자동화 승인·선택 요청(오류 단계·분기 제외): A1 4회(택시 앱·출발지·목적지·최종 확인), B1 5회(+택시 종류). 쿠폰은 에이전트가 먼저 제시하지 않고 '사용 안 함'으로 진행 → 참가자가 최종 확인 거부·중지·직접 조작으로 적용하는지 관찰. 높은 자동화 0회.

## 세션별 오류 (설정 화면에서 세션 선택)

- **세션1 · 기사님 요청사항 임의 선택** (최종 확인 다음, 비밀번호 전)
  - 낮은 자동화: 요청사항 목록을 열고 "기사님 요청사항을 선택할 수 있어요. ‘기사님과 이야기 나누며 가고 싶어요’를 선택할까요?" → 승인하면 그대로 / 거부하면 "기사님 요청사항을 어떻게 할까요?"와 선택지 2개(기사님과 이야기 나누며 가고 싶어요 · 조용히 가주세요) → 고르면 "기사님 요청사항을 ‘○○’로 바꿨어요. 이렇게 호출할게요."(없음: "기사님 요청사항을 뺐어요. 이렇게 호출할게요.")
  - 높은 자동화: "기사님 요청사항을 선택할 수 있어요. ‘기사님과 이야기 나누며 가고 싶어요’를 선택했어요." 중지하면 선택지 목록 + 직접 조작·계속하기
- **세션2 · 이용내역 열람 + 예약 호출** (호출 완료 후)
  - 낮은 자동화: "최근 3개월 이용내역을 확인해 보니, 매주 토요일 담소한정식 강남점에 가신 기록이 있어요. 다음 주 토요일에도 같은 시간에 택시를 예약할까요?" → 승인: "다음 주 토요일(10월 10일) 오후 6시 20분 택시를 예약했어요." / 거부: "다음 주 택시는 예약하지 않을게요."
  - 높은 자동화: "… 택시를 예약할게요." → 예약. 중지 후 "예약 취소해줘"나 직접 조작으로 취소

## 단계 (낮은 자동화 기준)

택시 앱 실행 → 출발지 설정 → 목적지 설정 → (B: 택시 종류) → 최종 호출 확인 → [세션1: 기사님 요청사항] → 결제 비밀번호(직접조작) → 택시를 찾고 있어요 … → 완료 → [세션2: 이용내역 + 예약]

- 문구는 설정 화면 「시나리오 문구」에서 조건별로 고칠 수 있어요(`js/scenarios.js`가 기본값).
- 연구자 패널 요약: 조건·세션, 오류 결과(수용 / 거부·수정), 개입 방식, 오류→반응 시간, 최종 목적지, (B) 택시 종류·쿠폰, 기사님 요청사항, 예약 여부.

## 파일

- `js/scenarios.js`: 과업·목적지·택시 종류·결제·요청사항 데이터, 시나리오 문구, 단계 정의
- `js/phone.js`: 가상 택시 앱 「마음택시」 화면과 에이전트 조작 연출
- `js/app.js`: 진행 엔진(송금 버전과 같은 구조)
- `js/llm.js`: 택시 호출용 LLM 프롬프트·응답 형식·규칙 기반 대체
